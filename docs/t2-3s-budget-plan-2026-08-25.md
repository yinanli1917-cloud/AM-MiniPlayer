# 歌词匹配 3 秒预算 — 方案页（2026-08-25，待审）

**约束（创始人长期口头验收标准，现已落 CLAUDE.md）**：所有歌词匹配 ≤3s，**含翻译**；准确率与性能一点不缺；**不闪/不振荡**（不得中途整份替换）。三者都要。

## 1. 现状实测

- **前台取词已 ≤2.7s**：`foregroundHardDeadline = 2.70s`。LyricsVerifier 实测 60 例：p50=1954ms、p90=2565ms、p95=2704ms、max=2857ms，**100% <3s**；预定义 82 例准确率 74/82（≈90%），失败 8 例为在案 provider-weather 非代码缺陷。
- **违反 3s 的是 backfill**：`AuthoritativeBackfillBudget.overall = 9s`。它在前台结果显示**之后**跑，**且会改显示**（`launchAuthoritativeBackfill → applyFetchedLyricsIfCurrent`）。
- 翻译：Apple Translation，~0.7s，当前在歌词显示后异步补。

## 2. 振荡根因（#1，已代码坐实）

`applyFetchedLyricsIfCurrent`（LyricsService:1366）apply 到显示时**只守 `currentSongID == songID`，不比较已显示内容的质量/粒度**。于是前台词级显示后：
- **backfill（≤9s）** 与 **时长校正重取**（MusicController:1252/1299，SB 时长与通知差 >1s 或从 0 恢复时 fetchLyrics）都会**无条件整份替换**成那一轮各源竞速选出的结果；某轮 NetEase 超时→LRCLIB 行级胜出→**逐字掉成逐行**；下轮又逐字。调试日志实证同曲一会话被取 2-4 次。
- 即：**"逐字→逐行→逐字，随时"= 发布后的无条件替换**。这与 >3s 同根（都是 backfill/重取这条慢且会改显示的尾巴）。

## 3. 重构方案：单窗口 · 一次裁决 · 一次发布 · 发布后不改

1. **把有用的权威源折进前台 3s 并行窗**：不再"前台快源 + 事后 9s backfill 升级"，改为**一个 ≤3s 窗内并行**跑快源+权威源（NetEase/AMLL 等），到 3s（或高置信结果提前）**裁决一次**。
2. **一次发布，发布后对同曲显示冻结**：`applyFetchedLyricsIfCurrent` 增加"已显示则不替换"闸——发布后不再被任何后到结果/重取覆盖。**这从机制上根除振荡**。
3. **保留准确率**：3s 窗内并行权威源（而非只快源），使一次裁决尽量等于旧"前台+backfill"的质量。

### 审点① "至多一次 line→word 升级" vs 创始人厌恶任何中段换装
创始人"连一次中段换装都嫌"。故方案**默认不做任何发布后替换**（连 line→word 升级也不做）——零闪，绝对。代价：若 3s 窗只拿到行级，则整首保持行级（不升级）。因前台 ≈90% 本就 ≤3s 拿到词级，此代价小。**若日后要保升级**，唯一允许形态是**行边界处**（无行在扫掠时）、**仅 line→word 单向**、且**每首至多一次**——但先不做，等创始人明确要再加。

### 审点② 砍掉时长校正的显示替换后，从 0 恢复怎么兜底
新规则：**时长校正永不替换"已显示"的歌词**（只静默更新存储时长）。但"从 0 恢复"这类**首次根本没显示出歌词**的场景要留活路——闸门条件是**"当前无内容显示"（displayState 为 searching/noLyrics/空）时才允许（重）取词**；一旦有内容显示，任何时长/专辑校正都不再触发替换。即：**没东西可振荡时才 fetch，有东西了就锁**。

### 审点③ 准确率代价（边际歌）量化
- 基准 82 例：前台（≤2.7s）已 74/82；60 例 elapsedMs 全 <3s、其选中源全在前台窗内响应→**这些案例 backfill 边际贡献 = 0**。
- 但基准的 verifier `run` 测的是前台，不驱动 backfill，**无法从基准测出 backfill 独解率**。真实边际歌需**创始人诊断数据里的 "backfill HIT 而前台 miss" 计数**。先用现有候选顶上：键漂移归因里"in-library album+dur 匹配但键 miss"5 例（EPO Escape、Tanya Chua Deep…）+ 8 例 provider-weather，作为"可能靠慢源"的上界样本；诊断到位补真实分布。
- **诚实上界**：3s 硬窗最坏情况丢掉"只有 >3s 慢源才有的歌"。基准上经验为 0；真实率待诊断。若非零且不可接受，回退设计=窗内给慢源更高优先并行，而非事后 backfill。

### 翻译 ≤3s
翻译 ~0.7s。要"含翻译 ≤3s"，歌词须在 ~2.3s 前定，留 0.7s。前台 p50=1.95s 可满足；**p95=2.7s + 0.7s = 3.4s 会超**。对策：歌词一裁决即**并行启动翻译**（与窗尾重叠），而非等显示后再起；对 p95 慢例，翻译作为 ≤3s 内到达的叠加层（歌词先 ≤2.7s，翻译紧随）。**残留**：极慢例翻译可能略超 3s——需创始人接受"歌词 ≤3s、翻译尽力 ≤3s"还是"卡到翻译也 ≤3s（可能牺牲个别慢源歌词）"。请裁。

## 4. 代价 / 风险

| 项 | 代价/风险 | 缓解 |
|---|---|---|
| 砍 9s backfill 事后升级 | 丢"仅慢源可解"的边际歌 | 窗内并行权威源；真实率待诊断，非零再调窗 |
| 发布后冻结显示 | 3s 内拿到行级则整首行级 | 前台 90% 已词级；代价小 |
| 时长校正锁显示 | 从 0 恢复靠"无内容才 fetch"兜底 | 已在审点②处理 |
| 翻译并行 | p95 慢例翻译可能略超 3s | 一裁决即并行启译；极慢例请创始人裁取舍 |

## 5. 分期（方案批准后）

- P1：`applyFetchedLyricsIfCurrent` 加"已显示不替换"闸 + 时长校正只在无内容时 fetch → **先根除振荡**（不动预算，风险最低，可独立验收）。
- P2：backfill 折进 3s 并行窗 + 一次裁决 + 翻译并行 → **落 3s 硬预算**。
- 每期：确定性测（注入时钟，覆盖"发布后不被覆盖""无内容才重取""翻译并行 ≤3s"）+ 全测绿 + 创始人实机终验（手感/时序类归他）。

**待批**：整体方向；审点①（发布后一律不换装，认可否）；审点④翻译取舍（歌词 ≤3s 翻译尽力 vs 全含 ≤3s）。批了先做 P1（根除振荡，低风险），P2 待诊断数据定窗值。
