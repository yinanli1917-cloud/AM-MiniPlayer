## 4. 分工与工作方式（创始人 09-10 定）
- 一个 worktree 一个独立会话（桌面 app 新 session）。会话内规划与验收 Fable 5.1 effort medium；写码、跑测试、搜资料由会话自己派 Sonnet 5 子代理做。
- 调研在各自会话里边做边搜，不集中到主会话。WT-C 的 Liquid Glass 调研必须走官方材料（WWDC25 Liquid Glass 系列 session、HIG Materials/Motion、glassEffect / GlassEffectContainer / glassEffectID / NSGlassEffectView 文档）加开源 Liquid Glass 动画实现，每个想要的动画先找到官方或开源对应物再动手。设计稿细节由创始人找参考后到相关页面确认。
- WT-E 不预设不可行：网易云、QQ 音乐、YouTube 已有大量做得好的第三方开源播放器工具，先研究它们怎么拿 now-playing 与控制播放，再定路线；仍禁私有 API。
- 会话之间有牵涉（同一文件、共享协议、时序依赖）用 session 间 message 直接沟通，不经创始人。
- 交付节奏：主会话按阶段收编各 worktree，出一个阶段性 binary bundle（build_app.sh，BuildInfo 列出本阶段包含的条目）。创始人一次性试完，在主会话给一次性反馈，主会话拆条转达各 worktree。
- 手感类最终验收归创始人；自验只做代码层面（单测、时间戳日志、假时钟、确定性回放）。先复现再修；不写白名单补丁；合回 main 即删 worktree 与分支。
