# nanoPod 动效实现规格：设置页演示台 + 引导「完成一步」

配套原型：同目录 `prototype.html`（单文件，A、B 两节，深浅色，手机宽度可看）。本文所有数字都能在原型代码里找到对应，原型是这份规格的可运行版本。作者：动效设计会话，2026-09-29。只出原型与规格，未改 `Sources/`、`Tests/`。

## 0. 结论先行

1. 设置页的演示台照系统设置「触控板」页重排：窗口顶部居中一块 **16:9 圆角矩形**演示台（创始人 09-29 已定 **300×169**；另两档 280×158 / 320×180 仅作对照，原型里保留切换控件标「已定」），自带壁纸式背景；悬停一行，这一行先亮，停满 150 ms 才切演示；离开后演完当前一轮，落在静息帧停。一次只有一段在动。
2. 演示动画的节奏以触控板录屏为准：主运动 **0.9 s 缓入缓出、无过冲**，动作之间停 0.7–1.4 s。
3. 引导「完成一步」做成 **7 状态的状态机**：预备 → 画勾 → 环长 → 火花 → 安定 → 交接（最后一步换成 合圈 → 礼花）。环的进度是一个可重定向的弹簧，被打断时速度不断、不回头。
4. 触觉建议：勾落下那一刻 `.levelChange` 一次，合圈 `.alignment` 一次。声音不加。
5. 引导卡的转场与微交互（§C）：卡按 260 宽、标题 15 / 正文 13 / 按钮 12 的可读档重画；卡片出现 → 位移（弹簧 + 箭头跟随换向）→ 新内容错峰换入，与打勾、火花无缝相接；高亮环有出现、呼吸（最多 3 周期）、跳转；控件藏着时用虚线环 + 幽灵光标 + 面板微光提示；按钮、链接、beat 行、待按态、「先到这里 / 这一步先不做」都有反馈。
6. 「减少动态效果」下：演示台只显示静帧；打勾动画只留线性填充、淡入淡出与触觉；转场退化为淡出 → 瞬移 → 淡入。

原型里有两处与 09-25 稿不同，需要创始人知道（详见 §D）：演示台高 120 → 140；演示动画用系统触控板的节奏，不用面板自己的弹簧。

### A.2 行与演示台的对应

| 状态 | 表现 |
|---|---|
| 指针进入行 | 行底色立刻变深（`--card-hover`，同触控板页悬停灰），0.12 s；此时演示台不变 |

| 拨动开关 | 不论有没有悬停：台上回放一次到新状态，然后停在静息帧 |
| 键盘焦点进入行 | 立即切换（无 150 ms 等待） |

### A.3 悬停意图

复用 `SharedControls.swift` 的 `ProgressHoverIntentEngine`：指针停留 **150 ms**，期间移动累计不超过 **4 pt**，才算「停住」；按鼠标事件判定，不定时采样。路过的行不切演示、不启动任何东西。原型里用 `pointerenter / pointermove / pointerleave` 与一个 150 ms 定时器复现，已用合成事件验证三种情形：快速路过（60 ms）不触发；停满触发；停留中移动超过 4 px 则重新计时。

### A.4 切换演示与「同一时间只动一段」

- 台上有前后两层。新演示在后层建好、`opacity 0→1`（0.28 s ease-in-out），前层同时 `1→0`。**淡出的那一层立刻冻结**在当前帧（不再走时钟），淡出结束后销毁。任何时刻最多一个时钟在走。
- 同一行再次悬停：如果它正在循环，什么都不做；如果已停在静息帧，原地从头循环，不做交叉淡入淡出。
- 离开行后的收尾：不硬停。运行器算出下一个「静息帧」的时刻 `stopAt = 下一个满足 t ≡ restT (mod loop) 的时刻`，走到就停，并把画面定在静息帧。静息帧由开关状态决定（开 = 效果完成态，关 = 初始态）。
- 没有悬停、没有开关回放时：演示台是静态视图，**不挂** `TimelineView`、不占合成。窗口 `orderOut` 或被遮挡（`NSWindow.didChangeOcclusionStateNotification`）时暂停时钟。
- 原型的自动轮播（顶栏开关）只用于给人看，不进产品。

### A.6 逐段演示

约定：`panelW` 是演示里的面板宽度，`em` 指 `panelW`（面板高 = 1.136 em，比例 250 : 284）；时间 `t` 是这一段的循环时钟，单位秒；`io` = 缓入缓出（A.5），`out` = `cubic-bezier(.2,.8,.2,1)`；`bump(t, t0, d)` = 在 `[t0, t0+d]` 内取 `sin(π·(t−t0)/d)`，其余为 0。每段都实现成一个纯函数 `render(t) -> DemoFrame`（无副作用，可用假时钟逐帧断言）。

#### A.6.1 全屏封面（`cover`，循环 6.2 s）

面板 `panelW = 110`，水平居中（左 105、上 30，底图 320×180 坐标，下同）。状态变量 `s ∈ [0,1]`：

| t (s) | 事件 | 曲线 |
|---|---|---|
| 0 – 0.9 | 静息，`s = 0`（封面留边） | |
| 0.9 – 1.8 | `s: 0 → 1` | io，0.9 s |
| 1.8 – 3.9 | 停，`s = 1`（铺满面板宽） | |
| 3.9 – 4.8 | `s: 1 → 0` | io，0.9 s |
| 4.8 – 6.2 | 停 | |

由 `s` 派生（单位 em）：封面边长 `lerp(0.68, 1.0, s)`；封面左 `(1−边长)/2`；封面上 `lerp(0.075, 0, s)`；封面圆角 `lerp(0.04, 0, s)`；标题条 top `lerp(0.885, 0.79, s)`、艺人条 `lerp(0.94, 0.845, s)`、控制行 `lerp(1.0, 0.915, s)`。铺满时封面阴影去掉。

- 开关回放（once）：开 = 播 `t ∈ [0.7, 2.7]`；关 = 播 `t ∈ [3.7, 5.4]`。
- 静息帧：开 `t = 2.7`，关 `t = 0.3`。
**底部模糊过渡（创始人 09-29 指出的断层，现已补上；做法照 `MiniPlayerView.swift` 全屏封面分支，只读）**：真实实现是两层——① 模糊底：封面图 `scaledToFill` 铺满整个面板，`blur(radius: 50, opaque: true)`（50 pt / 面板宽 250 = 0.2 em），叠 `artworkTone` 的饱和 / 对比 / 亮度 / 压暗；② 清晰封面：边长 = 面板宽，顶对齐，`mask` 为 `VStack { Rectangle(黑) ; LinearGradient(黑→透明).frame(height: 100) }`，即**封面自身最底 100 pt（= 0.4 × 封面边长）渐隐成透明**，露出下面的模糊底，所以封面到面板底色中间没有硬边，标题、艺人、控件压在这片模糊色上。演示里的对应：

| 层 | 演示做法 | 随 `s` |
|---|---|---|
| 模糊底 `bk` | 与封面同一幅画（天空渐变 + 落日 + 海面），放大成 1.4 em 见方、居中偏上（左 −0.2 em、上 −0.12 em，多出的一圈防止模糊边缘发虚），`filter: blur(0.17em) saturate(1.1)`（SwiftUI：`.blur(radius: 0.17 × panelW, opaque: true)`） | `opacity = s` |
| 清晰封面 `art` | 边长如上；`mask = LinearGradient(黑 到 (100 − 40·s)%，之后线性到 alpha (1 − s) 于 100%)`，即 `s = 0` 时无渐隐、`s = 1` 时最后 40 % 渐隐到全透明 | 渐隐带长度 `40·s` % |
| 文字、控件 | 白色，极淡文字阴影；不再加暗渐变 scrim（早先版本的暗渐变 scrim 是硬叠的一层，正是断层来源，已删） | |

终态验收：封面底边与面板底边之间任取一行像素，颜色是连续的（无硬边）；标题条落在封面渐隐带内。

- SwiftUI：一个 `KeyframeAnimator(initialValue: CoverFrame(s: 0), trigger: token)` 两条轨道 `[LinearKeyframe(0, 0.9), CubicKeyframe(1, duration: 0.9), LinearKeyframe(1, 2.1), CubicKeyframe(0, duration: 0.9), LinearKeyframe(0, 1.4)]`；或用统一的 `DemoClock` 调纯函数（推荐，见 A.8）。

#### A.6.2 贴边收起与换歌探出（`peek`，循环 8.4 s）

台 = 一块屏幕；右缘是屏幕边；顶部一条 macOS 菜单栏（A.6.0）。面板 `panelW = 104`，左 170、上 24。变量：

| 变量 | 事件 |
|---|---|
| `tuck` | 0.7 → 1（io 0.92 s）；6.7 → 0（io 0.92 s） |
| `cp`（小卡） | 2.4 → 1（io 0.8 s）；5.7 → 0（io 0.8 s）。**探出停留 2.5 s（3.2 → 5.7）= LiquidEdge autoPeek 真实时长** |
| `pulse` | `bump(t, 1.6, 0.9)`：换歌那一刻贴边条亮一下，亮完（2.5）小卡接手（09-29 由 `bump(t, 2.3, 1.0)` 提前，避免光晕落在已淡出的条上） |

派生：

### A.7 SwiftUI 结构

```swift
enum SettingsDemo: CaseIterable { case cover, peek, translation, translateTo, showHide, hideEdge /* + 通用段 */ 
    var loop: Double        // 秒
    var once: (on: ClosedRange<Double>, off: ClosedRange<Double>)
    func restTime(on: Bool) -> Double
    func frame(at t: Double, options: DemoOptions) -> DemoFrame   // 纯函数
}
struct DemoStage: View {          // 默认 300×169；内部画在 320×180 底图上再 scaleEffect(width / 320)
    let demo: SettingsDemo; let mode: DemoMode // .still | .loop | .once(on:)
    @Environment(\.accessibilityReduceMotion) var reduceMotion
    var body: some View {
        if reduceMotion || mode == .still { DemoCanvas(frame: demo.frame(at: demo.restTime(on:), options:)) }
        else { TimelineView(.animation) { ctx in DemoCanvas(frame: demo.frame(at: clock.time(ctx.date), options:)) } }
    }
}
```

- 每段演示是 `frame(at:)` 纯函数 + 一个只画不算的 `DemoCanvas`（`Canvas` 或 `ZStack`）。推荐用 `TimelineView(.animation)` 驱动纯函数，而不用 `PhaseAnimator`：纯函数可用假时钟逐帧断言，和「switch 回放一段区间」「离开后走到静息帧」这两件事天然吻合。
- 如果一定要用声明式 API：每个 `s` / `tuck` / `cp` 变量对应一个 `KeyframeTrack`，轨道值如 A.6 表；`KeyframeAnimator(initialValue:trigger:)` 的 `trigger` 用递增 token（悬停期间每轮结束 +1）。开关回放要从循环的中间开始，`KeyframeAnimator` 做不到，此时改用把两段区间拆成两个独立 keyframes 的 `enum Phase`。
- 交叉淡入淡出：`ZStack { ForEach(layers) { $0.opacity(...) } }`，前层 `.animation(.easeInOut(duration: 0.28), value: activeID)`；被淡出的层用 `.transaction { $0.animation = nil }` 冻结其内容（`TimelineView(paused: true)`）。
- 全部由 `RoundedRectangle` / `Capsule` / `Text` / `Image(systemName:)` 构成；无位图、无第三方。

### A.8 Reduce Motion

读 `@Environment(\.accessibilityReduceMotion)`（监听 `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`）：

- 不挂 `TimelineView` / `KeyframeAnimator` / `PhaseAnimator`，直接画 `restTime(on:)` 那一帧。
- 悬停只换静帧，无交叉淡入淡出（`Transaction(animation: nil)`）；台左下角的说明文字照样更新。
- 开关切换：静帧直接换成新状态。
- 静帧的选取：开 = 效果完成态（封面铺满 / 小卡探出 / 译文显示 / 面板可见），关 = 初始态。

### A.9 通用段两行（原型未画，参数留给实现）

沿用同一节奏：登录时启动 = 屏幕从暗到亮（0.4 s）+ 菜单栏 ♪ 点 `scale 0.6 → 1`（io 0.5 s）；在 Dock 显示 = 底部 Dock 胶囊 4 块灰块，nanoPod 块从上方落入并把邻块挤开（io 0.9 s），关时反向。

### A.10 验收（代码层）

1. 假时钟驱动 `ProgressHoverIntentEngine`：停留 149 ms 不切，150 ms 切；期间累计移动 4.1 pt 重新计时。
2. `DemoStage` 任何时刻只有一个活动时钟（计数断言）；淡出层的时钟已停。
3. `frame(at:)` 对每段在 `restTime` 的帧与设计稿数值相等；`t` 与 `t + loop` 帧完全相同（循环无缝）。
4. Reduce Motion 注入为真：`DemoStage` 的 body 不含 `TimelineView`（`Mirror`）。
5. 离开行后：运行器在 `stopAt` 停止；`stopAt` 满足 `(stopAt − restT) mod loop == 0`。
6. 手感（缓动、停顿是否舒服）由创始人亲自终验。

### B.4 打断规则（连点、完成中再完成）

原则：**视觉可以合并，进度永远单调，速度不断。**

1. 进度环用一个可重定向的弹簧 `ring: Val`。新的完成到来时只改目标（`target += 1`），弹簧从当前位置、当前速度继续走。SwiftUI 里等价于对同一个 `@State var ringProgress` 再调一次 `withAnimation(.spring(duration: 0.6, bounce: 0)) { ringProgress = new }`（SwiftUI 的弹簧动画在中途被覆盖时保持速度连续）。原型实测三连点：环单调不减，逐帧最大跳变 0.109 步，回退 0 次。
2. 上一次完成里**还没发生的 cue** 立刻快进：
   - 状态类 cue（勾画完、beat 变色、内容交接、进度目标）无动画地执行到位；
   - 装饰类 cue（火花、冲击波、礼花）**丢弃**，不补放；
   - 线宽 / 整体缩放弹簧回到静息值（线宽 0.1 s，缩放 `Spring(duration: 0.3, bounce: 0)`）。
3. 然后按正常流程启动新一次完成。连击计数 `combo`：两次完成间隔 < 4 s 则 `+1`（上限 3），火花 `16 + 4·combo` 粒。
4. 最后一步的合圈序列**不可被打断**（`B.finished` 之前忽略新的完成）。
5. 检测器回退（用户撤销）：忽略。完成是单调的。
6. 卡被关闭 / 用户点「以后再说」/ 窗口被遮挡：立刻快进到终态（同 2 的「状态类 cue」），不放装饰。
7. 中途切换「减少动态效果」：立刻快进当前序列，之后按降级规格走。
8. 慢放 0.25×（原型开关）只缩放时间，不改变任何顺序或参数，用于评审。

| 颜色 | 强调色 50 %、浅粉 `#FF8FA0` 25 %、金 `#FFB93F`（深色 `#FFC65A`）25 % | 强调色、金、紫 `#7A6BFF`（深 `#8F82FF`）、青 `#7FD6C2`、浅粉、白（09-25 稿建议取封面主色 3 个，无法取色时用这组） |
| 寿命 | 0.55 s，`alpha = 1 − easeIn(age/life)` | 1.8 s，末 0.5 s 线性淡出 |
| 冲击波 | 环心圆描边 1.5 pt，半径 `14 → 30`（out，0.5 s），`alpha 0.5 → 0`；礼花时叠两圈，第二圈延迟 120 ms | |

火花的颜色没有用白：浅色卡片是白底，白火花看不见。

### B.6 SwiftUI 映射

**不要用 `PhaseAnimator` 做主体。** 它在 `trigger` 变化时从头走 phase，不能在中途以当前速度接续，无法满足 B.4。建议：

```swift
@Observable final class CompletionChoreographer {
    enum Phase { case idle, anticipate, draw, grow, sparks, settle, handoff, seal, confetti }
    var ringProgress: Double = 0          // 单位：步；弹簧驱动
    var ringScale = 1.0, ringWidth = 5.5, numberOpacity = 1.0, checkDraw = 0.0, discRadius = 0.0 ...
    private var cues: [Cue] = []          // (fireAt: TimeInterval, essential: Bool, body: () -> Void)
    func complete()  { if busy { flushEssential() }; schedule(for: step) }
    private func flushEssential() { /* 状态类 cue 用 Transaction(animation: nil) 立即执行；装饰类丢弃 */ }
}
```

- `Cue` 由一个注入的 `Clock`（假时钟可推进）驱动；每个 cue 里用 `withAnimation(.spring(duration:bounce:))` 或 `.timingCurve(...)` 改上面的 `@Observable` 属性。这样整套序列是**确定性可回放**的，可以写单元测试。
- 环：`Circle().trim(from: 0, to: min(1, ringProgress/7))`，`.animation` 不加在 view 上，由 `withAnimation` 显式驱动（保证重定向速度连续）。
- 环内勾、beat 勾：`Path` + `.trim(from: 0, to: checkDraw)`；回弹用独立的 `scaleEffect`。
- 一次性的装饰（勾的 pop、环的弹跳）可以各用一个小 `KeyframeAnimator`（`SpringKeyframe(1.07, duration: 0.18, spring: .init(duration: 0.45, bounce: 0.35))` → `SpringKeyframe(1, ...)`），触发时若上一轮未完成就直接丢弃，视觉上不会有跳变，因为装饰类值量级只有 ±7 %。
- 数字变化：`.contentTransition(.numericText())` + `.transition`；交接里的数字上滚也可以直接用它，不必手写。
- 勾的符号如果不想手画：`Image(systemName: "checkmark")` + `.symbolEffect(.drawOn)`（macOS 26 的 SF Symbols 7 才有）；本机最低系统 macOS 14，因此规格按 `Path.trim` 写，这条留作以后升级的选项。

### B.9 从多邻国借了什么、没借什么

借的是**方法**，不是数字：

1. 动画做成**状态机**，工程实现与动画时序分离：多邻国用 Rive 的 State Machine 把动画（状态）和触发逻辑连起来，动画师改时序不动工程。我们对应：`Phase` + `Cue` 表 + 一个纯函数式的时序，设计参数集中在一张表里（就是本文 B.2–B.3），改数字不改流程。
2. 时序靠**多轮粗动画反复试**，节奏与能量是调出来的（多邻国 streak 动画一文）。我们对应：原型的慢放 0.25× 与确定性 `advance()`，评审时逐帧看。
3. **连续答对有升级**：多邻国在连续答对后插入「奖励小动画」。我们对应：连击 `combo`，间隔 < 4 s 的连续完成火花更多。
4. **多感官一起**：画面 + 声音 + 触觉一起讲同一件事。我们对应：画面 + 触觉；声音因音乐 app 的特殊性不加。
5. **成功反馈分层**：小事（beat）小反馈、大事（步）中反馈、终点（合圈）大反馈——小而准、大而少，不每次都放礼花。

没借的：吉祥物与夸张的角色表演（nanoPod 的气质是安静的）；声音。

## C. 引导的转场与微交互

创始人 09-29 新增：引导各步骤之间要有转场，指引本身要有动画，整套都要设计出转场（transition）和微交互（micro-interactions），不能只有打勾。原型第 C 节把 S0 → S1 → S2 → S3 →（S4）→ S5 → S6 → S7 串成一条可自动播放、可一拍一拍点、也可直接用鼠标在面板上做的演示。B 节的打勾编排原封不动地嵌在每一步的完成里：**打勾、火花 → 转场 → 新卡片**。

### C.2 卡片的出现与消失

**出现**（第一次出现，以及 S5 落角后、S6 收边后从新位置重新长出）。变换原点 = 箭头尖（卡朝锚点的那条边上、箭头所在的高度）：

| t (ms) | 变化 | 曲线 |
|---|---|---|
| 0 | 位置直接就位（不飞），`opacity 0`、`scale 0.94`、朝锚点方向偏移 10 pt | |
| 0 – 140 | `opacity 0 → 1` | `.easeOut` 0.14 s |
| 0 – ~500 | `scale 0.94 → 1`；偏移 10 → 0 | `Spring(duration: 0.36, bounce: 0.14)`（= `response .36 / damping .86`） |
| 60 + 40·i | 标题、正文、beat、按钮区、脚注依次 `opacity 0 → 1`、`offsetY 6 → 0` | 每块 0.18 s `out` |

### C.3 步骤之间的转场（与 B 节交接无缝相接）

一步完成的总时间线（t 从「检测到完成」起算；T0 为多个待勾 beat 的错峰偏移，通常 0）。B 节的 0–760 ms 不变，转场从 760 ms（`H`）起接上：

| t | 状态 | 变化 | 曲线 |
|---|---|---|---|
| 0 – 660 | 打勾、环长、火花（B.2） | | 同 B |
| 660 – 760 | 安定（让人看清） | | |
| **H = 760** | 卡内容淡出 | 标题、正文、beat、按钮区 `opacity 1 → 0`；同时高亮环淡出（0.14 s `in`）、幽灵光标与面板微光停掉、输出小菜单收起 | 0.14 s `easeIn` |
| H + 40 | **卡片位移** 到下一个锚点 | `x`、`y` 各一段弹簧，从当前速度接续（连点时不断速） | `Spring(duration: 0.5, bounce: 0.14)` |
| H + 40 | **箭头跟随** | 箭头在卡边上的高度 `bOff` 移向新锚点高度 | `Spring(duration: 0.42, bounce: 0.15)` |
| H + 40 → H + 160 | **箭头换向**（面板在卡的另一侧时） | 旧箭头 `opacity 1 → 0`（0.1 s `in`）；H + 160 换边；新箭头 `0 → 1`（0.16 s `out`） | |
| H + 140 | **换内容** | 换成下一步的标题、正文、beats；环内勾 `scale → 0.7` 退场，下一步数字上滚（`offsetY 6 → 0`、`scale 0.8 → 1`、`opacity 0 → 1`，0.22 s `out`，等价 `.numericText`） | |
| H + 140 + 40·i | 新内容依次淡入 | 标题、正文、beats、按钮区、脚注各 `opacity 0 → 1`、`offsetY 6 → 0`，0.18 s `out` | |
| H + 140 | **卡高变化** | 卡高从旧内容高度弹到新内容高度（新高度在 H 时刻已由不可见的测量副本算出） | `Spring(duration: 0.4, bounce: 0.15)` |
| H + 560 | **新高亮环出现** | 见 C.4 | |
| H + 1000 | 静止（可再次接受用户动作） | | |

#### C.4.2 「把鼠标挪过来」：控件还隐藏时

S1 开始时控件藏着，用三层提示，全部在用户把鼠标移到面板上时立刻停掉：

1. **环**：提示态（虚线）标出播放键将出现的位置，并按 C.4.1 呼吸 3 个周期。
2. **幽灵光标**：环出现后 0.6 s 起，一个箭头光标从卡的箭头尖出发，沿一条向上拱起 34 pt 的二次贝塞尔（控制点 = 中点上移 34）飘到面板封面下方 `(面板左 + 150, 面板上 + 190)`。一个周期 3.4 s：0 – 0.2 淡入到 0.92；0.25 – 1.15 位移（`cubic-bezier(.42, 0, .58, 1)`）；1.2 – 1.75 到位后一圈涟漪（26 pt 圆环 `scale 0.6 → 2.4`、α .55 → 0，表示「停在这里」）；2.05 – 2.35 淡出。**只放 2 个周期**。它是「指」，不代替用户，也不点击。
3. **面板微光**：面板边缘随呼吸 `g` 亮起：内描边 1.5 pt 强调色 α `.55·g`，外光 `6 + 22·g` pt、α `.35·g`。

用户移到面板上（停留 80 ms 后判定「控件浮出」）→ 幽灵光标 `opacity → 0` 立停，微光熄灭，环转待按态。若鼠标又离开面板：环回到提示态（虚线）、正文换成「鼠标再回到面板上。」；S2、S3、S4 同理（这三步的控件也要悬停才有）。

面板自己的悬停反应（被提示的对象）：封面 `0.68 → 0.48` 宽、上移，控件淡入，`Spring(duration: 0.4, bounce: 0.15)`（对应 `MiniPlayerView` 悬停弹簧 response .4 / damping .85）。

#### C.4.3 触控板手势示意

S5 的卡内示意**保留 09-25 稿的逐帧规格**（`onboarding/proposal.md` §8.7，来源 `trackpad-demo-frames.md`），不改动数值，只做两处适配：

- 因卡加宽到 260，示意按 1.15 倍显示（轮廓 96 × 72 → 约 110 × 83，圆点 11 → 12.6）；
- 时长乘 `--ts`（慢放 4 倍）。

一轮 3.55 s，播两轮后静止在 0.31 不透明的起点；三个变体：往角落推（`nudge`，位移 30 × 18）、横推向右 / 向左（`swipe` / `swipeL`，位移 36），方向随目标边。原型里落到**左下角**，所以第二拍用 `swipeL`。示意下方一行 11 pt 小字「点这里，代替双指手势」——**这一句只在原型里存在**，产品里手势是真的双指；示意区域在原型里可点，等同做一次手势。

### C.8 SwiftUI / AppKit 映射

- **窗口层**：卡片是 `TourCardWindow`（nonactivating `NSPanel`）。窗口 frame 的弹簧位移**不要**用 `NSAnimationContext`（不可重定向、不接续速度）；沿用 LiquidEdge 的做法——一个 `CADisplayLink` 驱动的逐帧弹簧积分器（`x`、`y` 各一个，`Spring(duration: 0.5, bounce: 0.14)` 对应 `ω = 2π/0.5`、`ζ = 0.86`），每帧 `setFrame(display: false)`。高度弹簧同理（`0.4 / 0.15`）。箭头位置 / 换向在 SwiftUI 内容里做（`TourBubbleShape(side:offset:)` 的 `animatableData = offset`）。
- **内容层（SwiftUI）**：`TourCardView` 读一个 `@Observable TourChoreographer`；各量按 C.2 – C.5 的表逐项 `withAnimation(.spring(duration:bounce:))` / `.timingCurve(...)`。错峰淡入：`ForEach(Array(items.enumerated()))` 里 `.opacity(phase[i])`、`.offset(y:)`，`phase[i]` 由 Choreographer 的 cue 表按 `0.06 + 0.04·i` 依次置位（不要用 `PhaseAnimator`，理由同 B.6：需要可打断）。
- **cue 表**：把 C.2 / C.3 / C.4 的每一行写成 `Cue(at: TimeInterval, essential: Bool, run: () -> Void)`，与 B 节同一个 `Clock`（假时钟可推进）。「essential」的 cue（换内容、置位状态、卡位移目标）在打断 / 快进时立即执行，装饰类（火花、礼花、呼吸、幽灵光标）丢弃——与 B.4 一致。
- **测量副本**：转场开始（H）时用一个不可见的 `TourCardView(content: nextStep).fixedSize(horizontal: false, vertical: true)` 量出下一步的自然高度，据此算位置；同一个函数在正文行数变化（待按态换文字）时重算。
- **高亮环**：`TourHaloWindow`（已有，不拦截鼠标）内一个 `Canvas` 或 `RoundedRectangle().stroke`，`x/y/w/h` 是一个 `Animatable` 四元组，跳转用 `.spring(duration: 0.42, bounce: 0.15)`；呼吸 3 周期用 `KeyframeAnimator`（一次性，`repeatCount` 显式为 3，之后不再驱动）。
- **幽灵光标**：不要用系统光标；一个 `Image(systemName: "cursorarrow")` 或 `Path`，放在 `TourHaloWindow` 里，沿贝塞尔用 `KeyframeAnimator`（`trigger` = 步骤 id），播两轮后 `paused`。
- **微交互**：`ButtonStyle` / `.onHover`；beat 行悬停用 `.onHover` 触发 `TourChoreographer.peek(beat:)`。
- **空闲成本**：无动作时没有任何 `TimelineView` / `CADisplayLink` 在跑；呼吸、幽灵光标、手势示意都有轮数上限，播完即停。卡窗口 `close()` 后 `WindowAnimationCensus` 的清单必须回到引导前（09-25 稿 §11）。

### C.9 验收（代码层，手感由创始人亲自终验）

1. 假时钟驱动 Choreographer：从 S1 检测到完成起，`t = 760 ms` 卡内容开始淡出；`t = 800 ms` 卡位置目标已更新；`t = 900 ms` 内容已换；`t = 1320 ms` 高亮环出现。
2. `place(...)` 纯函数：面板在右半屏 → 卡在左侧、箭头在右；在左半屏 → 反之；`beakOffset` 始终落在 `[24, h − 24]`；`y` 始终落在 `[菜单栏 + 10, 屏高 − 10 − h]`。
3. 换向：位置目标的 `side` 变化时，箭头 `opacity` 序列为 `1 → 0 → 1`，换边发生在 `opacity = 0` 的帧。
4. 打断：转场进行中再次收到完成，卡的目标位置直接更新为最新一步；速度不归零（位置序列一阶连续，二阶差分无跳变）。
5. 待按态：S1 beat 1 完成后进入待按；`hover` 序列 `false → true → false` 驱动 `bodyMode: base → armed → away`；卡高在每次换文字后 0.4 s 内到达新的自然高度。
6. 提示三层在鼠标进入面板后同一帧内熄灭（幽灵光标 `opacity = 0`、微光 `= 0`、呼吸停止）。
7. 呼吸与幽灵光标的轮数上限：3 与 2；超过后 `TimelineView` / display link 已停（计数断言）。
8. 「这一步先不做」：环的进度不变；`haptic` 调用次数 0；粒子数 0；下一步的环内数字 = 序号。
9. Reduce Motion 注入为真：卡与环的 `scale` 恒 1；粒子 0；幽灵光标、呼吸不出现；自动播放仍能到 S7。
10. 字号：`TourCardView` 中标题 / 正文 / beat / 链接 / 按钮的字号分别为 15 / 13 / 13 / 12 / 12（源码断言），卡宽 260。
