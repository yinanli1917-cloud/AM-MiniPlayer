# T2 · Bug #2 首字空白 — 调查现状（2026-08-25）

创始人报：放着放着，最开始那个字突然空白。要求：代码层复现。本页记录已排查路径与仍需的一条触发信息。

## 已排查（静态 + 代码路径）

1. **per-glyph 签名门（`applyMainWordFloatGlyphLayers`）— 普通行已排除**。字形层 `string`/`bounds` 只在 `EmphasisGlyphLayerSignature`(text,width,height,fontSize) 变化时设，但**签名与字符串是原子同设**（:2147-2149），且 `prepareForReuse` **不清字形层字符串、不重置签名**——所以复用后 glyph[0] 的字符串始终 = 当前 glyph[0]，不会出现"签名匹配但字符串为空"。普通行无空字路径。
2. **强调层 hide-in-base × overlay 分裂（`applyHiddenEmphasisText`）— 仅当首词是强调词**。强调词从整行基底文本里被"挖空"（hidden），改由 `emphasisGlyphLayers` 单独绘制；若某帧基底挖空持续、而强调字形层被隐藏/未设，则该强调词空白。**但强调词罕见**（少数被风格化的字），与"放着放着最开始那个字"这种普遍描述不太吻合——除非他那首歌首词恰是强调词。
3. **光栅化裁剪（settled 行 `shouldRasterize`）— 居中文本下不太可能**。settled 非活跃行会光栅化到行 bounds 缓冲；越界 ink 会被裁。但歌词**居中**，首字不在层左缘、rect.minX>0，通常不越界。存疑但证据弱。
4. **粒度升级瞬态**（#1 家族）：行级→词级切换那一帧 `mainTextLayer.string=nil` 而 per-glyph[0] 尚未设 → 可能一帧首字空——但那是**一帧瞬态**，非"放着放着突然、持续空白"。

## 结论：需要一条触发信息才能精准复现

静态分析无法唯一定位"普通行首字持续空白"。这是手感/像素级视觉缺陷，headless 像素捕获当前在重负载下 flaky（cacheDisplay capture-blank），状态级断言又抓不到"层在但被裁/被挖空"的像素结果。**按创始人自己的规则，手感类缺陷他可提供录屏**——这正是需要它的场景。

**请创始人给以下任一，我即可做确定性复现 + 修**：
- 一段出现"首字空白"瞬间的**录屏**（最有用），或
- 复现那首歌的**歌名**，外加三个判断：① 空白的是"当前正唱那行"的首字，还是**固定某行/首行**的首字？② 那首字所在的词是否是**被放大/强调**的字（karaoke 里明显比别的大）？③ 空白**何时**出现——切到该行时、唱到一半时、还是这行唱完/滚上去 settle 之后？

这三点分别对应上面候选 2/3/4，能一次锁定路径。拿到后我用 T0 那套注入时钟 + 定向状态/像素断言复现，再修。
