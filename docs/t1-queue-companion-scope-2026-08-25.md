# T1 · 伴生定位下的队列编辑思路（2026-08-25，不写码）

创始人拍板：产品=Apple Music 的**伴生窗口**，只保留最高频最顺手的操作，不做完整播放器；路线 B（换 ApplicationMusicPlayer 当播放器）**否决**。本页在此约束内重想"队列编辑"，回答两问：①最大化产品力的最高频操作子集是什么；②路线 A 那个窄口子值不值得做。

## 先厘清一个用词错位

用户嘴里的"队列"= Music 的 **Up Next 瞬态队列**。T1 已证：这个东西在公开 API 里**无对象、无入队/重排/删除动词**（见 [t1-queue-edit-feasibility](t1-queue-edit-feasibility-2026-08-21.md)）。所以"编辑队列"在系统播放器上**根本做不到**——这不是投入多少的问题，是 API 天花板。既然路线 B 已否决，任何"改 Up Next 顺序/移除下一首/插播下一首"都不在可交付范围。结论先行：**不承诺、不宣传任何"编辑 Up Next"能力。**

## 关键事实：最高频的那个操作，已经做完了

伴生窗口里用户对"接下来播什么"最高频的动作不是"重排/删除"，而是**"跳到那首"**——看到列表里想听的，点一下直接播。这个**已实现**：`PlaylistView.SongRow` 是个 Button，点击走 `playTrack(persistentID:)` →库曲用 `play (track of current playlist whose id …)`、`am:` 曲用 MusicKit。Up Next 与 Recent 行都可点即跳。

也就是说：**伴生定位下队列交互的产品力大头（导航/跳转）已经在手**。剩下想加的"编辑"三件套（移除/重排/插播）恰好全落在 API 做不到的那一侧。

## 最高频操作子集（可行 × 伴生合适），按价值排序

| 操作 | 可行性 | 现状 | 建议 |
|---|---|---|---|
| 点行跳到该曲（jump-to） | ✅ ScriptingBridge/MusicKit | **已实现** | 打磨可发现性/反馈，别再加"编辑"错觉 |
| 下一首/上一首/播放暂停 | ✅ | 已实现 | 保持 |
| Shuffle / Repeat | ✅ | 已实现 | 保持 |
| Love/收藏 当前或列表内曲目 | ✅（app 已有 favorites 通道） | 部分 | **可加**：列表行滑动/长按 Love，高频且零风险 |
| 看 Up Next / Recent | ⚠️ 仅歌单上下文；电台/流媒体下为空 | 已实现 | **补空态文案**：电台/AM 流下明说"无队列信息"，别让空列表像 bug |
| 移除"下一首" | ❌ 真队列不可写 | — | 不做（见下） |
| 重排 Up Next | ❌ | — | 不做 |
| 插播下一首 / 加入队列 | ❌ 无入队动词 | — | 不做（只有路线 B 能做，已否决） |

## 路线 A 那个窄口子：不值得做

路线 A =当当前播放是"库用户歌单"时，用 `delete track` / `move track` 改**底层用户歌单**来间接实现"移除/重排"。实测三件套在用户歌单上确实能跑，但作为产品功能它是**负分**：

1. **语义是错的**：用户以为在"把这首从待播里拿掉"，实际是**永久改他保存的歌单**。伴生窗口静默改用户曲库=数据完整性脚枪，违背"伴生、不侵入"的定位。
2. **覆盖面窄**：只在"从库歌单播放"时有效。Apple Music 歌单/专辑/电台/系统智能歌单**全不支持**——而这些恰是多数人的常用播放来源。做了也大半场景用不上。
3. **反馈不可控**：`current playlist` 是只读引用，改当前正在播的歌单是否即时反映到播放尚未确认；电台下 `current playlist` 直接报错。
4. **维护成本 vs 回报**：为一个"只在少数场景生效、还会误改用户库"的功能写状态机、加确认弹窗、处理失败回滚，投入不小，产品力却是负的。

→ **建议：明确弃做路线 A。** 与其加一个脆弱且会误伤用户库的"伪队列编辑"，不如把已可行的**跳转/Love/空态**打磨到顺手。

## 一句话给创始人

伴生定位下，"编辑 Up Next 队列"在系统播放器上是 API 天花板（路线 B 已否决即封死此路）；但**队列交互最高频的价值——点一下跳到那首——已经做完了**。下一步产品力不在"加编辑"，而在把**跳转的手感 + Love + 电台空态**做扎实。路线 A 的窄口子（改库歌单冒充队列编辑）语义错、覆盖窄、会误改用户库，**建议不做**。
