**抽帧方法**：`ffmpeg -vsync 0 -vf scale=720:-2` 逐帧原生抽取（无跳帧无补帧），共 412 帧，`scratch/v3/frames/f_0001.png`…`f_0412.png`。用 `ffprobe -show_entries frame=pts_time` 拿到每帧的真实时间戳（`scratch/v3/frame_times.txt`），下文时间均按该时间戳换算，不是按恒定帧间隔假设的。所有几何测量（宽高/收缩曲线）用 numpy 对每帧与"纯背景帧"(`f_0010.png`,无任何 UI)做逐像素差分、阈值化、取包围盒，逐帧算出，不是目测缩略图读数——这一步是为了直接回应"never downsample"的教训：缩略图 contact sheet 只用来定位大致窗口，所有结论性数字来自原生像素。

全片只有 **4 段材质相关的动作**：T0 胶囊条浮现、T1 胶囊条→球体收缩变形（核心）、一次性"熄灭再点亮"脉冲、T3 球体消散。中间是一段 ~5 秒的静止循环（球体呼吸/高光旋转），其材质行为也一并记录。

## 1. T0 — 胶囊条浮现（materialize）

逐帧包围盒（差分阈值法，原生 720×436 坐标）：

| 帧 | t(ms) | 视觉不透明度估计 | 说明 |
|---|---|---|---|
| f18 | 300.0 | 0% | 纯背景，无任何痕迹 |
| f19 | 316.7 | ~10% | 仅文字字形轮廓极淡的"鬼影"，胶囊本体（面板色块）完全不可见，说明**文字比面板先出现**（或两者同时起步但面板 alpha 曲线更慢） |
| f20 | 333.3 | ~40-45% | 面板色块出现，边缘高光(rim)出现，背景桥塔/云仍强烈透出 |
| f21 | 350.0 | ~70% | 面板更实，背景透出减弱 |

### 2.1 尺寸变化的关键结论（回应"任一维度是否有整体缩放过冲 overshoot"）

**高度几乎不参与收缩**：132px（静止胶囊）→133-137px（球体稳态），**只涨了约6%**。**宽度是唯一真正大幅变化的维度**：512px→139px，**收缩 73%**。也就是说这不是"整体等比缩小"，而是**几乎纯宽度方向的"捏合"**——因为胶囊的高度本来就已经等于球体的直径（胶囊的圆角半径=高度/2=66px，恰好就是最终球体半径），球体只需要把两端的直边"吃掉"即可，不需要压扁再重新拉圆。

**无回弹/过冲**：整条宽度收缩曲线（512→488→449→389→366→307→279→239→205→186→171→162→154→145→141→138）**单调递减、逐帧递减量递减（139后完全收敛，无一帧比稳态值更小再弹回，也无比 f52 更大的瞬时膨胀）**。同理高度全程 131-140px 之间抖动，无系统性凸起或凹陷。**结论：T1 是一次纯 ease-out 式收缩，没有弹簧过冲（overshoot/bounce），这与另一支旧参考视频（Amplify Video，见 §5）里胶囊↔卡片切换时出现的"鼓包/收颈"式非线性轮廓（那是形状路径的非线性，不是整体缩放过冲）不是同一种运动语言——本视频的球体收缩是纯尺寸插值，没有轮廓路径上的额外凸起。**

### 2.2 材质：不是形状裁切，是"内容淡出 + 连续几何插值 + 移动高光"三通道叠加

- f53：亮白高光扫入，此时形状还是满宽胶囊——说明高光动画的启动**领先于**几何收缩约 1 帧(~17-25ms)，不是收缩驱动高光，而是高光和收缩各自独立起步、几乎同步。
- f54起：文字("Search or Ask")与麦克风图标的 alpha 快速下降，与宽度收缩同步发生，f56 时文字已完全不可辨认——**内容消失比几何收缩略慢半拍，但在收缩过半时已经完全隐去**，不存在"收缩完了内容还没消失"的割裂感。
- 高光本体：从一条直的水平亮线（f53），到 f54-57 变成明显的 **S 形波浪**（振幅随宽度收缩而增大，像是material本身在"被挤压"时产生的液态形变，而非一条固定纹理贴图平移），到 f60-64 波浪进一步压缩成新月形，到 f65 起彻底转化为"球面高光弧"（贴着球体上边缘的一段亮弧+球体下半部的一片暖色反光区），这个过程**没有任何硬切/资源替换的痕迹**——高光形状本身连续形变，与几何轮廓连续形变是同一条运动曲线的两个表现,这正是founder说的"连续一镜运动"（continuous one-shot motion）的具体证据：不是"胶囊淡出、球体淡入"两个独立资源的交叉淡化，而是同一材质层在几何和高光两个通道上连续演化。

### 2.3 材质：色彩渐变（"玻璃渐变"）实测

在 f57（宽366px阶段）沿高光带采样 RGB（见 `scratch/v3/frames/f_0057.png`，裁剪框 x180-546,y120-255）：高光两端出现明显的冷暖分离——

- 高光左侧/上沿：偏冷白蓝，采样点如 `(176,223,255)`、`(140,166,207)`（蓝紫调白光）
- 高光中段/下沿：偏暖金，采样点如 `(253,253,225)`、`(255,238,207)`、`(240,215,164)`（奶油金色）

到球体稳态（f150/f200/f250，`scratch/v3/sheets_t/orb_zoom150.png` 等）该冷暖分离固化为一条**弧形分界线**：球体上半"深色区"与下半"暖金区"之间的边界不是一条纯白线，而是一条**带虹彩色散的窄边**（沿边界能看到蓝→白→金，甚至在 f250 观察到绿/红/紫的分光，见 `orb_zoom250.png`）——这是真实的色散/棱镜效果的视觉语言（即使渲染上大概率是预烘焙的渐变纹理而非物理光线追踪），构成founder所说的"glass gradient"。**这条冷暖分界线在整个静止循环里持续缓慢移动**（见 §3），不是定死的贴图。

外缘 rim：球体和胶囊在任何时刻都保持一圈**明确的亮白描边**（rim light），亮度在顶部最强、底部最弱，随几何形状同步收缩，没有断裂或消失过。

### 2.4 材质：折射/透镜化 lensing 检验

在胶囊条稳态（f30, `scratch/v3/sheets_t/leftcap_zoom.png` 放大截图）专门检查了胶囊与背景吊桥斜拉索交叠处：**胶囊内部完全看不到斜拉索的线条被弯曲穿过**——胶囊体是一个近乎不透明的深色渐变面（重度模糊+深色调），不是"透明可视穿背景"的 clear glass。折射/透镜效应**只体现在轮廓边缘**（rim 高光随曲率変化、亮度随曲率集中在圆角处最亮），而不是内容穿透。**结论：这是 Apple 文档里 `Glass.regular`（重模糊、偏不透明的默认材质）的视觉特征，不是 `Glass.clear`（更透明、背景可辨）的特征**——整个视频里没有看到清晰的"背景纹理透过玻璃并被弯曲"的证据，边缘的"透镜感"其实是 rim-light + 内部渐变共同营造的观感，不是真实像素级折射。

## 3. 静止循环（f102→f353，~4.4s）材质行为

- 球体几何完全恒定（139×137px 左右，±3px 抖动为抗锯齿噪声）。
- 冷暖分界弧线**持续绕球心摆动/旋转**：f150(t=2600ms) 暖金区在下方，f200(t=3475ms) 暖金区翻到上方，f250(t=4350ms) 暖金区回到下方——半周期 ≈875ms，一周期 ≈1750ms，是一个平滑、无缝、无跳变的循环动画（逐帧检查 150→200→250 之间没有找到第二处，全区间只用中值亮度法扫描过一次异常）。
- 这个"高光绕行"证明球体不是静态贴图，而是持续参与动画的材质层——是founder所说"continuous motion"在**静止态也不停**的体现，而不仅是转场时才动。

## 4. 一次性熄灭脉冲（f99-f101）

用逐帧平均亮度（球体包围盒内)量化：f93-f98 稳定在 94.1-94.2，**f99 骤降到 59.4（硬切，无渐变过渡帧）**，f99-f101 三帧完全持平在 59.3-59.4（说明是纯黑填充撑满 3 帧，不是渐变的谷底），**f102 又硬切回 96.7-97.0（比熄灭前的 94 还亮 ~2.6，说明重新点亮时球体色彩更饱和）**。全片用中值亮度扫描全部 254 帧（f60-353）确认这是**唯一一次**熄灭事件，不是循环节拍的一部分。视觉上（`scratch/v3/sheets_t/t2_fine.png`）熄灭态是一个几乎无描边的纯黑圆盘（"眼睛闭上"/光圈收缩的即视感），重新亮起时先出现更鲜艳的虹彩描边再回落到稳态亮度。**这段的功能含义不确定**（可能是"确认/推送新内容"的强调动效，也可能是源视频的编码/合成瑕疵——因为是硬切而非渐变，不能100%排除是源文件问题），如果创始人要照抄这个细节，建议先用另一份干净录屏交叉验证，本分析只如实记录像素证据。

## 5. T3 — 球体消散

| 帧 | t(ms) | 宽 | 高 | 亮度/清晰度 |
|---|---|---|---|---|
| f353 | 6166.7 | 141 | 138 | 稳态 |
| f354 | 6183.3 | 134 | 127 | 开始缩小 |
| f355 | 6200.0 | 129 | 121 | 边缘开始发虚(轮廓不再锐利) |
| f356 | 6216.7 | 120 | 114 | 明显虚化，描边已模糊成光晕 |
| f357 | 6233.3 | 85 | 93 | 只剩模糊光斑 |
| f358 | 6250.0 | — | — | 完全消失，回到纯背景 |

**结论**：T3 是**收缩 + 虚化(blur) + 淡出三个通道同步进行**的"融化"式消失，不是单纯 alpha 淡出（这点与 T0 的纯 alpha 浮现明显不对称——出现快而干脆，消失则带模糊）。整个过程仅 4-5 帧 / 75-92ms，非常快。

## 6. 与另一支旧参考视频（Amplify Video，胶囊↔卡片）的材质对比

复核了 `scratch/frames30/`、`scratch/zoom6/`、`scratch/zoom7/` 里对 `Amplify Video 2101065239332880384.mp4`（30fps 原生，2468×2160）膨胀/收缩转场的既有逐帧分析（`scratch/video-analysis-30fps.md`），并重新在原生分辨率下检查了 `zoom6/tile.png`（收缩颈部）、`zoom7/tile.png`（膨胀圆球）两组关键证据帧的**材质**（此前那版分析只谈轮廓/形状路径，没细看材质）：

- 该视频显示的是某个 App 自己的 UI（截图文字含"agent readable file""reactive donut UI"字样，是效率/Agent 类应用，不是系统级 Liquid Glass 组件)，其胶囊/卡片在膨胀和收缩全程始终是**纯色平面 + 均匀模糊**（黑色→灰色→奶油半透明的颜色插值），**没有任何 rim 高光、没有冷暖色散、没有可辨识的移动高光带**——与本次新视频（Search-or-Ask→球体）里持续存在的 rim light + 冷暖渐变高光形成直接对照。
- 也就是说：**"无 glass gradient"的founder反馈精确命中了差距**——旧参考视频本身也没有真正的 Liquid Glass 材质语言（它可能压根不是系统组件，只是普通毛玻璃/模糊卡片），而新视频里的球体才展示了 Apple 当前 Liquid Glass 该有的"边缘描边 + 内部色散渐变 + 移动高光"这套材质语言。两支视频合起来看：**旧视频提供的是"轮廓路径可以怎么非线性形变"的参考（鼓包/收颈），新视频提供的是"表面材质应该长什么样"的参考（rim+gradient+highlight）——我们的实现要同时对齐这两者，缺一不可。**

## 7. 对我们实现的启示

### 7.1 API 核对（均通过 `mcp__apple-dev-mcp__search_technical_documentation` / Apple 官方 JSON 端点核实，非[未验证]的都附官方原文）

| API | 签名/声明 | 用途对应 | 平台 |
|---|---|---|---|
| `View.glassEffect(_:in:)` | `nonisolated func glassEffect(_ glass: Glass = .regular, in shape: some Shape = DefaultGlassEffectShape()) -> some View` | 给胶囊条/球体本体套 Liquid Glass 材质 | iOS/iPadOS/Mac Catalyst/macOS/tvOS/watchOS **26.0+** |
| `Glass.regular` | `static var regular: Glass` — "The regular variant of the Liquid Glass material." | §2.4 判定这条视频用的是 regular（重模糊偏不透明），不是 clear | 同上 26.0+ |
| `Glass.clear` | `static var clear: Glass` — "The clear variant of glass." | 如果想要背景真正透过弯曲穿过，需要 `.clear`，但本视频没有证据显示用了 clear | 同上 26.0+ |
| `Glass.tint(_:)` | `func tint(Color?) -> Glass` — "Returns a copy of the structure with a configured tint color." | §2.3 冷暖渐变可能部分靠 tint 叠加，但更像是自定义渐变遮罩而非纯 tint（tint 是单色，不能产生沿边界的双色分离） | 同上 26.0+ |
| `Glass.interactive(_:)` | `func interactive(Bool) -> Glass` — "Returns a copy of the structure configured to be interactive." | 若要按压/悬停时材质有反馈可加，本视频未观察到交互态证据 | 同上 26.0+ |
| `GlassEffectContainer` | `init(spacing: CGFloat?, content: () -> Content)` — "Creates a glass effect container with the provided spacing, extracting glass shapes from the provided content." | T1 收缩若用两个独立 view（胶囊/球体）表达，需要包在同一个 container 里才能让系统做形状插值+高光过渡 | 同上 26.0+ |
| `View.glassEffectID(_:in:)` | "Associates an identity value to Liquid Glass effects defined within this view." | 让胶囊和球体两个视图共享同一个"材质身份"，是系统判断"这是同一块玻璃在变形"而不是"两块玻璃交叉淡出"的关键 | 同上 26.0+ |
| `View.glassEffectTransition(_:)` | "Associates a glass effect transition with any glass effects defined within this view." | 挂载下面两种过渡策略之一 | 同上 26.0+ |
| `GlassEffectTransition.matchedGeometry` | `static var matchedGeometry: GlassEffectTransition` — "Returns the matched geometry glass effect transition." | **T1（胶囊→球体）应该用这个**——它负责在两个不同形状/位置的 glass 之间做几何插值，对应我们观察到的"宽度连续收缩、高度几乎不变、高光连续形变"这条单一路径，而不是两份资源交叉淡出 | 同上 26.0+ |
| `GlassEffectTransition.materialize` | `static var materialize: GlassEffectTransition` — "...will fade in content and animate in or out the glass material but will not attempt to match the geometry of any other glass effects." | **T0（浮现）和 T3（消散）应该用这个**——官方原文明确说它是"淡入/淡出，不做geometry匹配"，正好对应我们测出的 T0 是纯 alpha 淡入（无几何变化）、T3 是淡出+虚化（也不是形状插值）；两段转场不该用同一个 transition 类型 | 同上 26.0+ |
| `GlassEffectTransition.identity` | `static var identity: GlassEffectTransition` — "The identity transition specifying no changes." | 循环态（§3）如果高光绕行是用 timeline 而非真实几何变化实现，本体材质本身应保持 identity，另用叠加层做高光旋转 | 同上 26.0+ |
| `GlassButtonStyle` / `GlassProminentButtonStyle` | "A button style that applies (prominent) glass border artwork based on the button's context." | 若球体最终承担按钮职能，可直接复用而非手搓描边 | 同上 26.0+ |
| `DefaultGlassEffectShape` | "The default shape applied by glass effects, a capsule." | 印证 §1 的测量结论——胶囊态圆角半径=高度/2，正是系统默认胶囊形状，无需手写 corner radius 插值 | 同上 26.0+ |
| `matchedGeometryEffect` | 经典 API，独立于 Liquid Glass | 如果不满 26 目标或想要更手动的控制，可作为 `glassEffectID`+`matchedGeometry` 的替代/补充，但拿不到系统原生的材质插值（rim/色散），需要自己叠加渐变层模拟 §2.3 | 早于 26，[未通过本次检索核实具体最低版本号，按既往经验 iOS 13+] |

### 7.2 分工判断：哪些能力公开 API 能做到，哪些大概率需要自己搭

**公开 API 基本能覆盖的**：
- 形状插值本身（胶囊→球体，宽高非对称收缩）：`GlassEffectContainer` + 共享 `glassEffectID` + `.glassEffectTransition(.matchedGeometry)`——这是系统内置行为，理论上不需要手写插值曲线。
- T0/T3 的淡入淡出：`.glassEffectTransition(.materialize)`，文档原文就是"fade in content and animate glass material, no geometry matching"，与我们测到的两段行为定义完全吻合。
- 外缘 rim 高光：`.glassEffect(.regular, in: shape)` 本身就带这层材质渲染，不需要手画。
- 按压/交互反馈（如果要加）：`Glass.interactive(true)`。

**大概率需要自己搭 / 公开 API 没有直接开关的**（标注 [未验证] 表示没有在 Apple 文档里找到对应符号，是基于本次像素分析+SwiftUI 已知能力做的推测）：
- **[未验证]** §2.3 那条随收缩形变、且左右两端冷暖分色的"S 形移动高光带"——`GlassEffectContainer` 的系统材质渲染目前没有文档证据表明会自动产生"沿边界移动的双色高光"，这更像是一层独立的 `LinearGradient`/`AngularGradient` 遮罩叠加在 glass 之上，随几何同步动画（用同一个插值进度驱动 shape 和 gradient 的 phase）。需要自己在 `GlassEffectContainer` 内部或上层叠加一个跟随形变进度旋转/平移的渐变 mask。
- **[未验证]** §3 循环态里持续绕球心旋转的冷暖分界线——这是一个独立的、与转场无关的周期动画（周期 ≈1.75s），建议用一个 `TimelineView` 或显式角度动画驱动一个叠加的 `AngularGradient`/自定义 `Canvas` 描边层，`Glass` API 本身不带"待机时持续旋转的内部高光"这种行为。
- **[未验证]** §4 的熄灭脉冲——如果确定要做，这是一次性的纯色黑场硬切（非渐变），可以用简单的 `Color.black` 覆盖层配合极短（2-3帧）的 opacity 切换实现，不需要 Liquid Glass API；但鉴于它只出现一次且是硬切，建议先跟创始人确认这是否是有意为之的设计还是源视频瑕疵，再决定要不要复刻。
- **折射/透镜化**：本视频全程没有观察到真正的背景像素级弯曲（§2.4），如果之后要做"背景真正透过并弯曲"的效果，那是 `Glass.clear` 的范畴而非 `.regular`，但即便是 `.clear`，系统级折射强度和范围目前没有公开可调参数的文档证据——**[未验证]**，如果需要精确控制折射量级，大概率要用 `.clear` 搭配手写的位移/扭曲 shader（`layerEffect`/Metal）来加强,因为系统默认的 clear 折射强度未必够"抢镜"。

### 7.3 与项目现状的落点

对照 `banned-patterns.md` 里"资深项目在 CALayer/隐式动画上踩过的坑"，这次的关键新增结论是：**founder 说的"没有连续一镜运动"，命中的是我们目前很可能用的是"两个独立 view 交叉淡出"（opacity crossfade）而不是"同一个 glass 身份做 matchedGeometry 插值"**——这两者在慢放/逐帧下的差异非常显著（交叉淡出会有一段"两个形状同时半透明叠加"的帧，而 matchedGeometry 插值全程只有一个轮廓，只是这个轮廓本身在变形）。建议下一步用本文档 §2 的逐帧宽高表（f53→f71，17 帧、~317ms）作为验收基线，去对照我们自己实现在同样窗口下是否也能做到"高度几乎不变、宽度单调收缩、无过冲"这条曲线，而不是先入为主假设"液态"就该有 bounce。
